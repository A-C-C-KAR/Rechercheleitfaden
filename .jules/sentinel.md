## 2024-05-24 - [CRITICAL] XSS via contenteditable fields
**Vulnerability:** The application uses `contenteditable` elements heavily for user input, instead of standard input fields or textareas. These `contenteditable` elements accept rich text natively, allowing a user to paste HTML elements directly, including potentially malicious `<script>` tags, event handlers (like `onload`), or other XSS vectors.
**Learning:** In a pure static HTML environment relying on `contenteditable` rather than inputs, we must manually intercept `paste` events to enforce `text/plain` input, preventing rich HTML injection. Standard sanitization tools aren't typically present in such static HTML/JS projects, making client-side event interception vital.
**Prevention:** Always attach a global or specific `paste` event listener that checks if the target is `contenteditable`, calls `e.preventDefault()`, extracts `text/plain` from the clipboard, and inserts it manually using `document.execCommand('insertText', false, text)`.
