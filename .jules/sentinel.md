## 2026-07-19 - Contenteditable XSS Vulnerability
**Vulnerability:** The application extensively uses `contenteditable` elements for user input without intercepting paste events. This allows users (or attackers tricking users) to paste rich HTML payloads directly into the DOM. This can result in Cross-Site Scripting (XSS) if malicious scripts are injected and subsequently executed when viewing or processing the page.
**Learning:** `contenteditable` elements naturally accept rich HTML content by default. In an application where only plain text input is expected from these fields, relying solely on backend sanitization (or having none in a purely frontend app) leaves a massive blind spot for DOM-based XSS attacks.
**Prevention:** Always intercept `paste` events on `contenteditable` elements when only plain text is intended. Prevent the default behavior and manually extract only the `text/plain` data from the clipboard using `e.clipboardData.getData('text/plain')`. Insert this plain text using `document.execCommand('insertText', false, text)` to ensure it is handled purely as text and any HTML tags are safely escaped.
