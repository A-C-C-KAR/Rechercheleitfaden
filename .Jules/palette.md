## 2024-07-14 - Loading States and Main Thread Blocking with html2pdf.js
**Learning:** The `html2pdf.js` library executes synchronously in a way that blocks the browser's main UI thread. If you update the DOM (e.g., adding a loading spinner or changing button text) immediately before calling `html2pdf()`, the browser may not have a chance to paint the updated UI before the main thread is locked up, resulting in missing user feedback during a long-running process.
**Action:** When providing UX feedback before generating a PDF (such as a loading spinner or "Loading..." text), wrap the heavy `html2pdf()` generation call inside a `setTimeout(() => { ... }, 100)` block. This yields execution back to the browser momentarily, ensuring the loading state is actually rendered to the user before the thread is blocked.
